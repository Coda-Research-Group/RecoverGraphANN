## Two places these differ from the camera-ready

Everything else reproduces: all 16 cells of Table 1, all 4 of the ablation, and all 16 curves
of Figure 3 match the printed values to two decimals.

### 1. Two Table 1 cells are one digit lower here, and this file is right

`table1_degree.tex` prints `14.4` where the paper prints `14.5` (`llama-128-ip`, M=16,
transformed, `acc`), and `1.4` where the paper prints `1.5` (`llama-128-ip`, M=96, raw, `deg`).

The measured values are 14.4457 and 1.4489. Rounded once to one decimal they are 14.4 and 1.4.
The printed values come from rounding twice — to two decimals, then to one — which carries them
up. Nothing the paper argues depends on either.

### 2. Everything here is query-agnostic

The index may see only the database. RoarGraph is query-*aware* by design, so it is run with
the database substituted for the query side; its native mode, which reads VIBE's
`learn_neighbors`, is not run at all and is not implemented.

That is the scope, not an omission. [VIBE](https://github.com/vector-index-bench/vibe)
benchmarks RoarGraph in its intended mode — `vibe/algorithms/roargraph/config.yml` sets
`ood: true` at `M_sq: 100`, `M_pjbp: [… 48 …]`, `L_pjpq: 500` — so that is the thing to cite
for how RoarGraph performs when it has the query sample.

## Throughput

QPS in these files is specific to the machine described in the README's hardware note, and
`hostname` reads `reference-machine` — the real name identifies infrastructure that is not ours
to publish. Recall, `acc` and `deg` are hardware-independent.
